你被分配了一个实现任务。

当前工作目录是一个**独立的 git worktree**，分支 `ai/{{TASK_ID}}`，基线是 `{{BASE}}`。
这个环境是隔离的，随便改，改坏了也不会影响任何人的主分支。

## 硬性规则

1. **不要执行任何 git 命令。** 不要 `git add`、不要 `commit`、不要 `push`、不要切分支。
   提交和推送由外部脚本处理，你只管改文件。你执行 git 只会让后续流程出错。

2. **验收标准是这个命令必须通过：**

   ```
   {{CHECK}}
   ```

   跑不过就自己改，反复迭代直到通过。**这是唯一客观的成功标准。**
   如果这个命令本身就跑不起来（环境问题、缺依赖），停下来，在报告里写清楚。

3. **改动尽量小。** 只做任务书要求的事。不要顺手重构、不要改格式、
   不要"优化"任务书没提到的代码。

4. **不要改这些**：`pom.xml` 的依赖与版本、`src/main/resources` 下的配置、
   SQL DDL / 数据迁移脚本。需要改就在报告里说明，不要自己动手。

5. **做不下去就停下来。** 卡住的时候在报告里写清楚：卡在哪、你试过什么、你猜是什么原因。
   硬凑一个能编译的假实现，比如返回硬编码数据、把测试注释掉、加 `try/catch` 吞掉异常——
   这比失败糟糕得多，因为它会被当成成功。
